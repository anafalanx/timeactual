## Recovery implementation and evidence

`tools/install.lua` groups archives by destination, preserving overlay order.
It stages extraction, records relative filenames and SHA-256 digests in
`.kuu-installed.json` inside the installed tree, and replaces the old tree
with a recoverable rename sequence. Missing files, changed bytes and invalid
records force repair. Downloads are verified before use. Previous presence
stamps under `.tools/installed/` are no longer completion evidence.

Tcl/Tk's compiled-output record is removed before rebuilding and recreated
only after the required outputs and content inventory exist. The compiled
tree itself is rebuilt in place, so an interrupted build can leave partial
outputs and must be rerun.

`tests/test_prereqs.lua` uses `tests/prereqs_server.py`, a Python standard
library loopback server. **17 checks passed on both Kuu 0.5 and 0.6**:
empty tools, long paths, overlays, reuse, corruption, missing files, malformed
records, bad cache/upstream bytes, killed downloads, recovery between renames,
offline reuse/repair, relocation with spaces, and concurrent repair.
The fixture stubs Tcl/Tk compilation; it does not replace the real cold build.

Kuu's long-path hashing defect was fixed during this work, with **838 Kuu
checks and native static analysis passing**. The installer has an explicit
extended-path compatibility branch for published 0.5. Always refresh the
root 0.6 executable from the current build when using an unreleased binary;
earlier binaries also report 0.6 but lack this fix. See the [Kuu handoff](https://github.com/anafalanx/kuu/blob/main/docs/handoff-2026-09-10_193511.md).

Before the recovery changes, the independent application build passed 2,191
engine checks, nine task checks and the packaged self-test. The initial
adoption also exercised a moved checkout with spaces and invalid inherited
tool overrides. The complete test task has not been rerun with the final
recovery recipe.
